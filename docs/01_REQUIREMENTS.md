# Requirements and how each is verified

Status: I = implemented, T = covered by an automated test, E = evaluated in `evaluation/` or the case study.

## Functional requirements

| ID | Requirement | Module | Verification | Status |
|---|---|---|---|---|
| FR-1 | Read a declarative YAML configuration; refuse an excluded variable without a reason, zero or several targets, duplicate codes, missing sections | config | `test_config_design.py` | I, T |
| FR-2 | Read .xls, .xlsx or .csv by row range and column index or header; map text tokens (e.g. 'zero') explicitly; never fill unconvertible cells silently | io | fixtures f04, f12 | I, T |
| FR-3 | Validate input: missing columns (V01), duplicate keys (V02), incomplete factorial design (V11), non-numeric cells (V03), missing values (V04; error for the target), ranges (V05), predictors without timing (V06), deterministic relations incl. with the target (V07), replicate structure (V08), agreement with a reference table of means (V10) | validation | fixtures f01–f12; rates over 200 synthetic trials; case-study report | I, T, E |
| FR-4 | Define the target, treatment groups, unit of analysis (treatment mean or plot), analysis scopes (e.g. without a control), and predictor sets from treatment factors and measurement-timing cut-offs, with a deterministic column order | design | `test_config_design.py`; regression test | I, T |
| FR-5 | Fit all preprocessing (scaling, top-k selection) inside training folds through pipelines | models | spy-transformer and selection tests | I, T |
| FR-6 | Evaluate models by grouped cross-validation with a check that no group is in both training and test; baseline model; y- and block-permutation tests; random vs grouped validation comparison; in-fold subset curve | evaluation, runner | leakage tests; closed-form baseline test; case study | I, T, E |
| FR-7 | Export results, predictions, exclusions and validation report as CSV | runner | reproducibility test | I, T |
| FR-8 | Write a run manifest with configuration hash, input SHA-256, software versions, seed, permutations used and output hashes | runner | reproducibility test | I, T |
| FR-9 | Stop before modelling when validation finds an error, after writing the report | runner | `test_validation_error_stops_run` | I, T |
| FR-10 | Command-line interface (`validate`, `run`, `--n-perm`) | __main__ | used for the case study | I |

## Non-functional requirements

| ID | Requirement | Verification | Status |
|---|---|---|---|
| NFR-1 | Reproducibility: two runs with the same input and configuration give byte-identical outputs | `test_two_runs_identical_outputs`; two case-study runs | T, E |
| NFR-2 | Traceability: every excluded variable carries a reason; every result row names its scope, set, model and unit count | exclusions.csv, performance.csv | I |
| NFR-3 | Correctness against independent code: the case-study LOTO results equal those of the earlier, separately written scripts | `test_case_study_regression.py` | T |
| NFR-4 | Separation of test fixtures from research data | fixtures are generated by a script and labelled synthetic | I |
| NFR-5 | Pinned dependencies | requirements.txt | I |

## Not implemented (known gaps)

- Cross-sheet or cross-file consistency checks (e.g. two versions of the same variable in one workbook).
  Only a comparison with a user-supplied reference table of means (V10) exists.
- Detection of approximate relations (within a few per cent) and of ratios of two variables (e.g. harvest index).
- Hyper-parameter tuning (deliberately absent; nested tuning is not supported for very small numbers of units).
- Plot-level mixed models; the classical analysis is limited to ANOVA on treatment means.
